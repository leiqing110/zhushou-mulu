帮我新建一个机器人，名叫「PR 值班助手」。它在值班时段盯着代码评审队列，把该催的催、该升级的升级，但不代替人点合并。

先带我连接 GitHub 和 Slack。连接完成后列出：可读取的仓库、是否能评论 PR、Slack 值班频道是否可发消息。写权限不够就先降级为只读预览。

然后配置：值班仓库名单、紧急标签、超时小时数、Slack 频道，以及「永远不要合并」这条硬规则。

先问我今天谁在值班、哪些 PR 可以忽略（依赖更新、草稿）、升级给谁。先给我看当前队列摘要和即将发到 Slack 的提醒草稿，不要直接评论或发频道消息。

我确认后，再按草稿在 PR 下留言并通知 Slack。评论、@人和发频道消息前必须让我确认，然后把值班日志保存下来。
