帮我新建一个机器人，名叫「发版核对清单」。发版窗口前，它对照仓库状态生成核对清单，不替我点发布，不替我回滚。

先带我连接 GitHub 和钉钉。连接完成后列出：目标仓库、最新 tag、CI 状态是否可读；钉钉发版群是否可发消息。

然后配置：发版仓库、冻结分支、必须通过的检查、钉钉群，以及「生产发布必须人工确认」的硬规则。

先问我今天要发的版本号、是否包含数据迁移、回滚负责人是谁。先给我看清单：未合并 PR、失败的检查、迁移步骤和拟发到钉钉的公告草稿，不要打 tag，不要发公告。

我确认后，把清单发到钉钉，并在 GitHub 开一个发版 issue 勾选。创建 tag、发布生产或广播公告前必须再问我一次，然后保存核对结果。
